## 2. 共通の関門（全テーマ）

### 着手前

1. `git fetch origin` → `origin/main` から作業ブランチを切る（リモートのブランチ名は環境の規約に従う。2テーマ目以降でpushが拒否されたら、**forceなし**で `git push origin HEAD:<規約の接頭辞>-pageAudit-<テーマ名>` と新しい名前にする）
2. JST取得は `python3 -c "from datetime import datetime,timezone,timedelta;print(datetime.now(timezone(timedelta(hours=9))).strftime('%Y-%m-%d %H:%M JST'))"`

### マージ前（1つでも満たさなければマージしない）

| # | 関門 |
|---|---|
| M1 | `git diff --name-only origin/main...HEAD` がテーマの「触ってよいファイル」＋`notes/pageAuditProgress.md` の範囲に収まる |
| M2 | テーマの「消えるべき語」が変更後0件、「残るべき語」が期待件数（件数はスクリプトで数え、PR本文に前後の数を書く） |
| M3 | `python3 scripts/lintGuard.py` が通る |
| M4 | 表示の変わるテーマは、Playwright（幅390px）で対象ページを開き、JS例外0・NaN/undefined/null表示0・横はみ出し0。コントラストを直したテーマは対象要素が4.5:1以上。**Playwrightが使えない環境では、CSS/JSを変えるテーマは実施せず記録して次へ**（文言だけのテーマは実施してよい） |
| M5 | GitHub Actions の走行中WFが0本（`gh run list --status in_progress` か GitHub MCP で確認） |
| M6 | JST 11:00〜11:40 の外 |

M5・M6 を満たさないときは10分待って再確認。3回で満たさなければ、そのテーマを「保留」と記録して次へ進む。

### マージ後

1. テーマに「再生成WF」があれば `workflow_dispatch` で実行し、完了を待つ
2. 新しい main のコミットSHAを固定して生成物を取得し、M2・M4 を**生成物に対して**やり直す
3. 失敗したら、そのsquashコミットを `git revert` した新しいPRを同じ関門で通してマージし、「差し戻し」と記録して次へ

### `[updates]` 行

読者の画面が変わるテーマだけ、PR本文に1行。形式 `[updates] ページ名 / 本文`。事実だけを書く（「〜を直しました」「〜を削除しました」）。煽り語・感嘆符なし。

### 絶対禁止（違反しそうなら、そのテーマを実施せず記録して次へ）

- `git clean` / force-push / rebase / `git add -A` / `git add .`（パスを明示して add）
- 生成物の直接編集（第3節の対応表に従い正本を直す）
- `predictions/`・`verify_log.csv`・`HARAN_TH`・`results/*.json`・`docs/players/profile.json` の変更
- `scripts/motor/app.jsx` 末尾39行、コピーガード関連コード
- 同じテーマを2回PRにする。別のCodeセッションを並行で立てる
- 台帳に無い改善・リファクタ

### 全体の打ち切り

関門の失敗で差し戻しが2テーマ連続したら、以降を止めて `notes/pageAuditProgress.md` に理由を書き、それをPRにして終了する。
