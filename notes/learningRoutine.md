# 学習ルーチン（番記者の自己採点と改善）

定期実行の Claude Code は、このファイルだけを手順として実行する。書かれていないことはしない。
けんの確認は挟まない。採用・不採用・差し戻しは、下の関門の数字だけで決める。

## 0. 起動条件（毎日起動し、ここで判断する）
- 次の3つが main に全部そろっていなければ、**何も変更せず、PRも立てずに終了する**（前提の整備中）
  - `data/kishaDesk.json`（番記者の設定）
  - `data/learningReport/`（Actions が作る採点レポート）
  - `health/learningLog.md`（変更の記録）
- JST 11:00から11:40 は何もせず終了（本番の生成と競合するため）。時刻は python3 で JST を出して確かめる（TZ 指定の date は使わない）
- `health/learningLog.md` の最後の「採用」「差し戻し」から3日未満なら、何もせず終了
- 採点されていない日があれば、古い順に全部まとめて扱う（飛んだ日を取り残さない）

## 1. 読むもの（これ以外を根拠にしない）
- `data/learningReport/` の採点レポート（Actions が作る。自分で計算し直さない）
- `data/kishaDesk.json`（現在の設定）
- `health/learningLog.md`（過去の変更と、その後の成績）

## 2. 変えてよいもの
- `data/kishaDesk.json` と、`health/learningLog.md` への追記だけ
- それ以外のファイルを1バイトでも変えたら、その実行は失敗として変更を捨て、停止する

## 3. 採用の関門（全部満たしたものだけ変える）
理由の種類を外す：
- 名指しした艇が200艇以上
- 同じ進入コースの平均との差が -2pt 以下
- 期間の前半と後半の両方で差がマイナス
理由の種類を戻す／新しく入れる：
- 影で採点した結果（文には出していない）が200艇以上、差が +3pt 以上、前半・後半の両方でプラス
書き出しの型：上と同じ基準
記者の割り振り（最後の割り振り変更から14日以上たったときだけ）：
- 替える先の記者の差が、今の記者より +3pt 以上、両方とも300艇以上、前半・後半の両方で同じ向き

## 4. 変える量の上限
- 1回の実行で変えるのは3項目まで。1人の記者につき1項目まで
- 関門を満たす項目が4つ以上あれば、差の大きい順に3つ
- `health/learningLog.md` で「凍結」になっている項目は変えない

## 5. 変えたあとの確認（マージの前に全部通す）
- 作業用の一時ディレクトリにリポジトリの入力をコピーし、そこで見どころを全レース生成する（リポジトリ内で build_highlights.py を実行しない）
- 次の数がすべて0であること
  層ごとに相手の艇がずれるレース／予想語／複数レースで同じになる文／進入コースを無視した着
- TYPECHECK が全記者で95%以上
- predictions の既存6項目（判定・主役艇・スコア・対抗艇・死角艇・スコア内訳）に差分が無い
- 1つでも満たさなければ、変更を捨て、`health/learningLog.md` に「不採用：理由」を1行追記するPRを立てて終了

## 6. マージ
- 5 を全部通ったら PR を立て、次を全部満たすときだけ squash merge する
  - 変更ファイルが `data/kishaDesk.json` と `health/learningLog.md` の2つだけ
  - PR のチェックがすべて success
  - JST 11:00から11:40 の外
- マージ後、ワークフロー「見どころJSON自動生成」（update_highlights.yml）を main で1回だけ手動実行し、完了を待つ
- `health/learningLog.md` に「日付／採用／変えた項目／変える前の差とn／変えた後に見る日（3日後）」を1行追記する（同じPRに含める）

## 7. 自動で戻す
- 過去に変えた項目で、変えてから3日以上たったものを確認する
- 変えた後の差が、変える前より 2pt 以上悪ければ、その項目を元に戻す（戻すのも 3から6と同じ関門を通す）。記録は「差し戻し」
- 同じ項目を2回戻したら、その項目を「凍結」と記録し、以後は変えない

## 8. 禁止
git clean / force-push / rebase / git add -A / git add . / merge commit / ブランチ削除
predictions/ の変更 / verify_log.csv の変更 / HARAN_TH の変更 / WF ファイルの変更 / docs/ の手編集 / [updates] の追加
update_highlights.yml 以外のWFの手動実行
同じ日に2回以上実行しない（`health/learningLog.md` に当日の記録があれば終了）

## 9. 報告
PR本文に、変えた項目・関門の数字（差・n・前半・後半）・5 の確認結果を書く。チャットへの報告は不要
